# 🎯 Cursor Workflow для PoolAI - Робота з документацією

## ⚠️ КРИТИЧНО ВАЖЛИВО

**ВСІ `.md` файли ПОВИННІ бути в `docs/` каталозі!**

Корінь проекту містить ТІЛЬКИ:
- `README.md` - основний README
- `README.uk.md` - український README

## 📋 Правила роботи з документацією

### Коли користувач просить створити документацію:

1. **Визначте категорію**:
   - Статус проекту → `docs/status/`
   - План розробки → `docs/development/`
   - Нова функція → `docs/[feature-name]/` або відповідна категорія
   - Архів → `docs/archive/`

2. **Створіть файл в правильному місці**:
   ```bash
   # ПРИКЛАД: Користувач просить "створити план наступних кроків"
   # ❌ НЕПРАВИЛЬНО: NEXT_STEPS.md в корені
   # ✅ ПРАВИЛЬНО: docs/development/NEXT_STEPS_PLAN.md
   ```

3. **Оновіть індекс** (якщо потрібно):
   - Додайте посилання в `docs/README.md`

### Коли користувач посилається на файл:

1. **Якщо файл не знайдено в `docs/`**:
   - Перевірте `docs/archive/` - можливо файл архівний
   - Якщо не знайдено, створіть в відповідній категорії `docs/`

2. **Якщо файл в корені**:
   - Перемістіть в `docs/archive/` (якщо старий) або відповідну категорію
   - Оновіть всі посилання на файл

### Коли користувач просить оновити концепт:

- Використовуйте: `docs/concept/poolAI_concept.txt`
- НЕ створюйте новий файл в корені!

## 🔧 Робота зі скриптами (.sh файли)

### Правила для скриптів

1. **ВСІ `.sh` файли ПОВИННІ бути в `scripts/` каталозі!**

2. **Коли користувач просить створити скрипт**:
   - Створюйте в `scripts/`
   - Додавайте shebang: `#!/bin/bash`
   - Додавайте опис в коментарях
   - Оновлюйте `scripts/README.md`

3. **Приклади**:
   ```bash
   # ✅ ПРАВИЛЬНО
   scripts/my_script.sh
   
   # ❌ НЕПРАВИЛЬНО
   my_script.sh (в корені)
   ```

## 🔍 Перевірка перед commit

Перед кожним commit перевірте:

```powershell
# Перевірка: чи є .md файли в корені (окрім README)
cd S:\rust\poolAI
Get-ChildItem -Filter *.md -File | Where-Object { $_.Name -ne 'README.md' -and $_.Name -ne 'README.uk.md' }

# Перевірка: чи є .sh файли в корені
Get-ChildItem -Filter *.sh -File
```

Якщо знайдено файли - перемістіть їх в `docs/` або `scripts/` відповідно!

## 📝 Приклади правильних дій

### ✅ ПРАВИЛЬНО:

```
Користувач: "створи план розробки"
→ Створюємо: docs/development/DEVELOPMENT_PLAN.md
→ Оновлюємо: docs/README.md (додаємо посилання)
```

```
Користувач: "оновлю статус проекту"
→ Оновлюємо: docs/status/CURRENT_STATUS.md
```

```
Користувач: "створи документацію для нової функції X"
→ Створюємо: docs/[category]/X_DOCUMENTATION.md
→ Або: docs/X/README.md (якщо потрібна підкатегорія)
```

### ❌ НЕПРАВИЛЬНО:

```
Користувач: "створи план розробки"
→ ❌ Створюємо: DEVELOPMENT_PLAN.md в корені
```

```
Користувач: "оновлю концепт"
→ ❌ Створюємо: poolAI_concept.txt в корені
```

## 🎯 Швидкий довідник

| Запит користувача | Дія |
|-------------------|-----|
| "створи план" | `docs/development/` |
| "оновлю статус" | `docs/status/CURRENT_STATUS.md` |
| "документація для X" | `docs/[category]/X.md` |
| "архівний файл" | `docs/archive/` |
| "концепт" | `docs/concept/poolAI_concept.txt` |
| "створи скрипт" | `scripts/script_name.sh` |
| "shell script" | `scripts/script_name.sh` |

## 🔄 Автоматична перевірка

Cursor автоматично:
- Створює файли в `docs/` згідно з `.cursorrules`
- Пропонує правильну категорію
- Попереджає про створення файлів в корені

## 📚 Структура для посилань

В документації використовуйте відносні шляхи:

```markdown
<!-- З docs/development/NEXT_STEPS_PLAN.md -->
[Current Status](../status/CURRENT_STATUS.md)
[Concept File](../concept/poolAI_concept.txt)

<!-- З docs/status/CURRENT_STATUS.md -->
[Next Steps](../development/NEXT_STEPS_PLAN.md)
```
