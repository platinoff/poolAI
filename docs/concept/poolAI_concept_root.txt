## 🏗️ Rust Architecture Principles (Updated for Rust 1.83+)

### **Zero-Cost Abstractions**
- Trait-based polymorphism without runtime overhead
- Compiler optimizes abstractions to native code (LLVM optimizations)
- Zero-copy operations where possible (serde, bytes)
- Generic programming with monomorphization

### **Memory Safety without GC**
- Ownership and Borrowing for safe memory management
- Arc<RwLock<T>> for shared mutable state (thread-safe)
- Lifetimes prevent dangling pointers (compile-time checks)
- No null pointer exceptions (Option<T> instead)
- Stack-based allocation with automatic cleanup (RAII)

### **Concurrency-First Design**
- Async/await for non-blocking operations (Tokio runtime)
- Tokio runtime for multithreading (work-stealing scheduler)
- Actor model for state isolation (message passing)
- Channels for communication (mpsc, oneshot, broadcast)
- Lock-free data structures where possible (atomic operations)

### **Type Safety**
- Strong typing prevents runtime errors (compile-time checks)
- Pattern matching for exhaustive handling (match expressions)
- Option<T> and Result<T, E> for error handling (no exceptions)
- Type inference reduces boilerplate (let bindings)
- Generic constraints ensure correctness (trait bounds)

### **Modern Rust Features (1.83+)**
- **Async traits** - Native async trait support (no async-trait crate needed)
- **Generic associated types (GATs)** - More flexible trait definitions
- **Const generics** - Compile-time constants in generic parameters
- **Improved error messages** - Better diagnostics and suggestions
- **Performance improvements** - Faster compilation and runtime
- **Enhanced tooling** - Better rust-analyzer, clippy, and cargo support

pub trait Repository<T> {

## 🎯 Rust Best Practices (Rust Book 2024/2025 Edition)

### **Module Organization** (Following Rust Book Chapter 7)
- Each module has a `mod.rs` file as the entry point (or `mod.rs` in directory)
- Sub-modules are declared in `mod.rs` and implemented in separate `.rs` files
- Public API is re-exported through `pub use` statements (convenience)
- Private implementation details are kept in sub-modules (encapsulation)
- Use `pub(crate)` for crate-internal visibility
- Use `pub(super)` for parent module visibility

### **Error Handling** (Following Rust Book Chapter 9)
- All functions that can fail return `Result<T, AppError>`
- Error types are defined in `core::error` module (centralized)
- Errors are propagated using `?` operator (ergonomic)
- Panic is only used for unrecoverable errors (`unwrap()` in tests only)
- Use `thiserror` or `anyhow` for error handling (if needed)
- Custom error types implement `std::error::Error` trait

### **Concurrency** (Following Rust Book Chapter 16)
- Shared state uses `Arc<RwLock<T>>` for thread-safe access (sync)
- Async functions use `tokio::sync::RwLock` for async contexts (async)
- Message passing via channels (`mpsc`, `oneshot`, `broadcast`) for communication
- Background tasks spawned with `tokio::spawn` (async runtime)
- Use `tokio::select!` for concurrent operations (async select)
- Prefer message passing over shared state (actor model)

### **Memory Management** (Following Rust Book Chapter 4)
- Ownership is explicit and checked at compile time (zero-cost)
- Borrowing is used for temporary access (references)
- `Arc` is used for shared ownership across threads (reference counting)
- `Rc` is used for single-threaded shared ownership (if needed)
- Lifetimes prevent dangling references (`'static`, `'a`, etc.)
- Use `Box<T>` for heap allocation when size is unknown at compile time

### **Testing** (Following Rust Book Chapter 11)
- Unit tests in `#[cfg(test)]` modules (same file or `tests/` submodule)
- Integration tests in `tests/` directory (separate compilation)
- Doc tests in documentation comments (`/// # Examples`)
- Mocking for external dependencies (mockall, mockito)
- Property-based testing with `proptest` (fuzzing)
- Use `#[should_panic]` for panic tests (expected panics)
- Test private functions through public API (best practice)

### **Documentation** (Following Rust Book Chapter 14)
- Use `///` for public API documentation (rustdoc)
- Use `//!` for module-level documentation (inner doc)
- Include code examples in documentation (`# Examples`)
- Use `#[doc(hidden)]` for internal APIs (hide from docs)
- Generate docs with `cargo doc --open` (local docs)
- Publish docs with `cargo doc --no-deps` (for crates.io)

## 🛠️ Development Environment & Build System

### **MSYS2 UCRT64 (Recommended for Windows)**

PoolAI is configured to use **MSYS2 UCRT64** as the primary development and compilation environment on Windows.

#### **Requirements**
- **MSYS2 UCRT64** - Primary development environment
- **Rust toolchain**: `stable-x86_64-pc-windows-gnu` (GNU toolchain)
- **MSYS2 UCRT64 shell** - Automatically used in Cursor/VS Code terminal
- **GCC/MinGW-w64** - Provided by MSYS2 UCRT64

#### **Terminal Configuration**
The project is configured for automatic MSYS2 UCRT64 shell usage:
- `.vscode/settings.json` contains terminal settings
- Terminal automatically launches in MSYS2 UCRT64 when opening a new terminal
- Environment variables `MSYSTEM=UCRT64` and `CHERE_INVOKING=1` are set automatically

#### **Rust Toolchain Setup**

**If Rust is not found in MSYS2 UCRT64** (`cargo: command not found`):

**Quick Fix** (Recommended - Automatic):
```bash
cd /s/rust/poolAI
bash setup_rust_path.sh
source ~/.bashrc
cargo --version
```

**Manual Setup**:

1. **Add Rust to PATH** (if Rust is already installed on Windows):
```bash
# Add to ~/.bashrc or ~/.bash_profile
echo 'export PATH="/c/Users/$USER/.cargo/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

2. **Or install Rust via rustup in MSYS2**:
```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
export PATH="$HOME/.cargo/bin:$PATH"
```

3. **Install GNU toolchain**:
```bash
# Install GNU toolchain for MSYS2
rustup default stable-x86_64-pc-windows-gnu

# Or for this project only
rustup override set stable-x86_64-pc-windows-gnu
```

4. **Verify installation**:
```bash
cargo --version
rustc --version
rustup show
```

**Note**: VS Code/Cursor settings have been updated to automatically include Rust PATH in terminal environment. See `setup_rust_path.sh` for automatic setup script.

#### **Benefits of MSYS2 UCRT64**
- **Compatibility**: Full Windows API compatibility through UCRT (Universal C Runtime)
- **Performance**: Optimized binaries for Windows
- **Libraries**: Easy access to libraries via pacman (MSYS2 package manager)
- **Integration**: Smooth integration with modern development tools
- **Debugging**: Support for GDB and other debugging tools

#### **Alternative Environments**
- **Linux**: Native compilation via standard Rust toolchain
- **WSL**: Can be used, but MSYS2 UCRT64 is recommended for Windows
- **MSVC**: Not recommended due to dependency issues (ring, gcc.exe)
