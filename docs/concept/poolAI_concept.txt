# PoolAI: Оптимизированная система распределенных вычислений

## 0. Майнинг нового поколения

### 0.1 Определение
Майнинг нового поколения - это процесс использования вычислительных ресурсов (CPU, GPU, DPU, ASIC) для обработки запросов генеративных нейронных сетей. В отличие от традиционного майнинга криптовалют, где вычислительная мощность направлена на решение криптографических задач, новый майнинг фокусируется на генерации полезного контента и решении реальных задач.

### 0.2 Компоненты майнинга
- **Вычислительные ресурсы**: CPU для общих задач, GPU для параллельных вычислений, DPU для специализированных операций, ASIC для оптимизированных задач
- **Генеративные модели**: Нейронные сети для создания текста, изображений, кода и других типов контента
- **Распределенная обработка**: Пул воркеров для эффективного распределения нагрузки
- **Система вознаграждений**: Награды за качество и скорость генерации контента

### 0.3 Преимущества нового майнинга
- Полезный выход: генерация реального контента вместо абстрактных вычислений
- Гибкость: возможность переключения между разными типами задач
- Эффективность: оптимизация использования ресурсов под конкретные задачи
- Масштабируемость: легкость добавления новых воркеров и типов задач

### 4.3 HTTPS/TLS Архитектура

#### 4.3.1 Варианты развертывания

**Вариант A: Встроенный HTTPS (Рекомендуется для production)**
```
Internet → PoolAI (HTTPS:443) → Internal Services
         ↑
   TLS termination в PoolAI
   - Let's Encrypt автоматическое обновление
   - Self-signed для разработки
   - Wildcard сертификаты для поддоменов
```

**Вариант B: Reverse Proxy (Рекомендуется для enterprise)**
```
Internet → Nginx/Apache (HTTPS:443) → PoolAI (HTTP:8080)
         ↑
   TLS termination в Nginx
   - Централизованное управление сертификатами
   - Load balancing
   - Дополнительная защита
```

#### 4.3.2 Этапы реализации HTTPS

**Этап 1: HTTP для разработки (MVP)**
- HTTP на localhost:8080
- Базовая аутентификация
- Подготовка архитектуры для HTTPS

**Этап 2: HTTPS для тестирования (Stage 2)**
- Self-signed сертификаты
- Встроенная TLS поддержка
- Тестирование в staging среде

**Этап 3: Production HTTPS (Stage 3)**
- Let's Encrypt автоматические сертификаты
- HSTS заголовки
- Perfect Forward Secrecy
- Certificate Transparency

#### 4.3.3 Конфигурация безопасности

```toml
[security]
# TLS/HTTPS настройки
enable_https = true
cert_path = "/etc/poolai/certs/cert.pem"
key_path = "/etc/poolai/certs/key.pem"
redirect_http_to_https = true

# Аутентификация
jwt_secret = "your-super-secret-key"
jwt_expiration = 3600  # 1 час
rate_limit_requests = 100  # запросов в минуту
rate_limit_window = 60  # секунд

# CORS настройки
cors_origins = ["https://poolai.example.com"]
cors_methods = ["GET", "POST", "PUT", "DELETE"]
cors_headers = ["Authorization", "Content-Type"]

# Безопасность заголовков
security_headers = true
hsts_max_age = 31536000  # 1 год
content_security_policy = "default-src 'self'"
```

## 9.5 Архитектурные принципы Rust

### 9.5.1 Zero-Cost Abstractions
- Trait-based полиморфизм без накладных расходов времени выполнения
- Компилятор оптимизирует абстракции до нативного кода
- Zero-copy операции где возможно

### 9.5.2 Безопасность памяти без GC
- Ownership и Borrowing для безопасного управления памятью
- Arc<RwLock<T>> для разделяемого изменяемого состояния
- Lifetimes предотвращают висячие указатели

### 9.5.3 Concurrency-First Design
- Async/await для неблокирующих операций
- Tokio runtime для многопоточности
- Actor model для изоляции состояния

### 9.5.4 Type Safety
- Строгая типизация предотвращает ошибки времени выполнения
- Pattern matching для исчерпывающей обработки
- Option<T> и Result<T, E> для обработки ошибок

## 9.6 Архитектурные паттерны

### 9.6.1 Actor Model
```rust
pub struct ModuleActor {
    state: Arc<RwLock<ModuleState>>,
    message_queue: mpsc::UnboundedReceiver<Message>,
}
```

### 9.6.2 Repository Pattern
```rust
pub trait Repository<T> {
    async fn get(&self, id: &str) -> Result<Option<T>, AppError>;
    async fn save(&self, entity: T) -> Result<(), AppError>;
    async fn delete(&self, id: &str) -> Result<(), AppError>;
}
```

### 9.6.3 CQRS Pattern
```rust
pub trait Command {
    async fn execute(&self) -> Result<(), AppError>;
}

pub trait Query {
    type Result;
    async fn execute(&self) -> Result<Self::Result, AppError>;
}
```

## 9.7 Rust Best Practices

### 9.7.1 Организация модулей
- Каждый модуль имеет файл `mod.rs` как точку входа
- Подмодули объявляются в `mod.rs` и реализуются в отдельных `.rs` файлах
- Публичный API реэкспортируется через `pub use` statements
- Детали реализации хранятся в подмодулях

### 9.7.2 Обработка ошибок
- Все функции, которые могут завершиться ошибкой, возвращают `Result<T, AppError>`
- Типы ошибок определены в модуле `core::error`
- Ошибки распространяются с помощью оператора `?`
- Panic используется только для невосстановимых ошибок

### 9.7.3 Concurrency
- Разделяемое состояние использует `Arc<RwLock<T>>` для потокобезопасного доступа
- Async функции используют `tokio::sync::RwLock` для async контекстов
- Передача сообщений через каналы (`mpsc`, `oneshot`) для коммуникации
- Фоновые задачи запускаются с `tokio::spawn`

### 9.7.4 Управление памятью
- Ownership явный и проверяется на этапе компиляции
- Borrowing используется для временного доступа
- `Arc` используется для разделяемого владения между потоками
- Lifetimes предотвращают висячие ссылки

### 9.7.5 Тестирование
- Unit тесты в `#[cfg(test)]` модулях
- Integration тесты в директории `tests/`
- Mocking для внешних зависимостей
- Property-based тестирование с `proptest`

### 9.7.6 Политика MSRV и издания Rust
- Явно фиксировать MSRV (минимальная версия Rust) в `rust-toolchain.toml`
- Обновлять MSRV только после CI/локальной проверки
- Планировать миграцию на Rust 2024 edition в отдельной задаче

### 9.7.7 Hygiene зависимостей и безопасность supply-chain
- Регулярно выполнять `cargo audit` и фиксировать уязвимости
- Использовать `cargo deny` для лицензий/дубликатов/уязвимостей
- Минимизировать зависимости и отключать лишние default features

### 9.7.8 Инструменты качества
- `cargo fmt` и `cargo clippy` в CI
- Политика `deny(warnings)` для release профиля (поэтапно)
- Логирование через `tracing` с явными контекстами

## 11. Среда разработки и сборка

### 11.1 Требования к окружению

#### 11.1.1 Windows (Рекомендуется)
- **MSYS2 UCRT64** - основная среда разработки и компиляции
- **Rust toolchain**: `stable-x86_64-pc-windows-gnu` (GNU toolchain)
- **MSYS2 UCRT64 shell** - автоматически используется в Cursor/VS Code терминале
- **GCC/MinGW-w64** - предоставляется MSYS2 UCRT64

#### 11.1.2 Конфигурация терминала
Проект настроен для автоматического использования MSYS2 UCRT64 оболочки:
- Файл `.vscode/settings.json` содержит настройки терминала
- Терминал автоматически запускается в MSYS2 UCRT64 при открытии нового терминала
- Переменные окружения `MSYSTEM=UCRT64` и `CHERE_INVOKING=1` установлены автоматически
- Рабочая директория терминала указывает на каталог проекта (`terminal.integrated.cwd`)

#### 11.1.3 Rust Toolchain Setup

**Если Rust не найден в MSYS2 UCRT64** (`cargo: command not found`):

1. **Добавить Rust в PATH** (если Rust уже установлен в Windows):
```bash
# Добавить в ~/.bashrc или ~/.bash_profile
echo 'export PATH="/c/Users/$USER/.cargo/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

2. **Или установить Rust через rustup в MSYS2**:
```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
export PATH="$HOME/.cargo/bin:$PATH"
```

3. **Установка GNU toolchain**:
```bash
# Установка GNU toolchain для MSYS2
rustup default stable-x86_64-pc-windows-gnu

# Или для конкретного проекта
rustup override set stable-x86_64-pc-windows-gnu
```

4. **Проверка установки**:
```bash
cargo --version
rustc --version
rustup show
```

### 11.2 Сборка проекта

#### 11.2.1 Компиляция через MSYS2 UCRT64
```bash
# В MSYS2 UCRT64 терминале
cargo build
cargo run
cargo check
cargo test
```

#### 11.2.2 Конфигурация Cargo
Файл `.cargo/config.toml` настроен для GNU toolchain:
```toml
[target.x86_64-pc-windows-gnu]
linker = "x86_64-w64-mingw32-gcc"
```

### 11.3 Преимущества MSYS2 UCRT64
- **Совместимость**: Полная совместимость с Windows API через UCRT (Universal C Runtime)
- **Производительность**: Оптимизированные бинарники для Windows
- **Библиотеки**: Легкий доступ к библиотекам через pacman (менеджер пакетов MSYS2)
- **Интеграция**: Плавная интеграция с современными инструментами разработки
- **Отладка**: Поддержка GDB и других инструментов отладки

### 11.4 Альтернативные окружения
- **Linux**: Нативная компиляция через стандартный Rust toolchain
- **WSL**: Можно использовать, но рекомендуется MSYS2 UCRT64 для Windows
- **MSVC**: Не рекомендуется из-за проблем с зависимостями (ring, gcc.exe)
